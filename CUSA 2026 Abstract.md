# A Broader Perspective on Diff and Merge in Engineering

This abstract presents the perspective of an OpenMBEE working group focused on the diff and merge problem for engineering models. OpenMBEE’s Model Management System (MMS) provides version control for structured data, and its current implementation Flexo provides a graph-native model management platform within that ecosystem. One of the main drivers for this work is SysML v2, which is both a major use case for Flexo and a domain where practitioners expect robust diff, merge, and model interchange behavior.

The core problem is simple: engineering models are not source code. In graph-based model repositories, two changes can be individually valid and still produce an invalid system when combined. A small satellite example illustrates the issue. One team upgrades the communications subsystem, another upgrades the thermal subsystem, and each branch passes on its own. But when the changes are merged, the combined model violates shared power, bus load, and ownership constraints. The merge problem is therefore not just about reconciling edits. It is about evaluating the merged model state.

Using Flexo as a case study, this work proposes a practitioner-oriented view of model merge with four layers: syntactic merge, structural checks, constraint evaluation, and simulation or human review. The main argument is that merge for engineering models should be treated as part of an engineering change process rather than only as a version control operation. The talk outlines a practical roadmap: start with true three-way diff and merge, add machine-checkable structural and domain constraints, and then grow toward a workflow that integrates analysis services, review gates, and organization-specific policies.
