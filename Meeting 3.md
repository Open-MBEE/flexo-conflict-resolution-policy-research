# Flexo - Diff / Merge Mind Melt

RecordingMar 31, 8:00am–9:00am

Zargham advocated a sequencing formalism for Diff and Merge across concurrent changes, not just pairwise. Siegl proposed a lightweight Git‑backed option (single‑file serialization, same frontends as Flexo) for feature branching. The group aligned on a SysML‑level JSON interchange via a kernel emitting KerML JSON and a higher‑level SysML JSON, better ontology modularization, and Git compatibility for behavioral oracles outside RDF. They discussed OpenMBE anchoring this with OMG and industry support. Next: Siegl drafts problem statements; Zargham prototypes a satellite demo.

Key topics:

- **N-way Diff/Merge formalism:** Michael emphasized modeling Merge as a sequencing problem that supports arbitrary N-way conflicts, not just pairwise, so we avoid lock-in to narrow cases and can specialize later without rework.
    
- **Git-based backend option alongside Flexo:** Daniel proposed a lightweight Git-backed option that serializes the full model as a single file (no triplestore) to simplify feature branching and onboarding, while keeping the same interfaces/UX as Flexo.
    
- **SysML v2 serialization and kernel architecture:** The team aligned on a higher-level SysML JSON interchange/persistence format (distinct from verbose KerML JSON) generated by a kernel that compiles SysML textual notation to KerML and can emit both canonical and lightweight serializations with better modularization/package management; OpenMBE could lead an implementation-first effort with OMG, with industry support Daniel can help organize.
    
- **Oracles and behavioral analysis in Diff/Merge:** Michael outlined oracles spanning deterministic checks over the canonical serialization, external simulation/analysis pipelines, and human review, noting executable behavioral models must live/version in Git (not RDF), so the Diff/Merge architecture must accommodate Git-native assets while supporting RDF/SysML views.
    
- **Funding and commercial layering:** Separate open-source OpenMBE efforts from commercial engagements, prioritize commercially valuable low-effort features to fund OSS, and use even small sponsorships from large firms as market signals to unlock more support.
    
- **Next steps:** Daniel will draft a clear, commercially grounded problem description and minimal example; Johannes will provide a simple SysML satellite model with machine-checkable oracles; Michael will build a worked demo including a behavioral oracle, while the group prototypes the SysML-level JSON and keeps the Diff/Merge layer backend-agnostic.
